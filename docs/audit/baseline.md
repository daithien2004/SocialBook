### Follow-up: self-hosted frontend fonts

The frontend build failure above was resolved after the baseline by replacing `next/font/google` with local Inter, Merriweather, and Noto Sans assets. `npm run build --workspace=frontend` now passes without fetching fonts during the build. The existing 9 lint warnings and design-token collision warning remain unchanged.

### Follow-up: typed domain failures

The baseline found 48 generic `throw new Error(...)` sites inside domain code. Domain validation and invariant failures now use `BadRequestDomainException`; missing child entities in chapter operations use `NotFoundDomainException`. This makes those failures map to stable 400/404 Problem Details instead of falling through as 500 errors. A later source scan found 23 remaining generic throws outside domain: startup/configuration and transaction guards, seed/migration safety checks, external-provider failures, uninitialized Chroma state, WebSocket ticket parsing sentinels, and namespace lifecycle guards. These have different semantics and should not all be converted to HTTP exceptions.

The missing-user case in `GenerateWsTicketHandler` now throws `NotFoundDomainException` instead of becoming an opaque 500. Missing chapters in audio jobs and unsupported reading-progress queue jobs use BullMQ `UnrecoverableError`, avoiding retries for permanent/invalid jobs. A focused unit test covers the WebSocket ticket not-found mapping.

### Follow-up: durable reading progress queue

WebSocket reading progress no longer waits in a process-local tracker. The gateway enqueues each accepted heartbeat into BullMQ; a 10-second delay and deduplication key per user/book/chapter coalesce pending updates. The worker executes the existing `UpdateProgressCommand`, preserving its domain rules and Mongo transaction. Queue jobs use the shared retry/backoff policy and failed jobs are retained for inspection. The full backend check passes (16 suites, 36 tests). The queue Redis uses AOF with `appendfsync everysec`, so a Redis host/storage failure can still lose the most recent fsync window; volatile client heartbeats that never reach the API cannot be recovered.

## Baseline findings

### Domain errors and invariants

- 48 occurrences of `throw new Error(...)` were found in domain folders. Many validate value objects/entities; replace by module-coded domain errors incrementally while keeping domain framework-free.
- Chapter entity protects paragraph/title/order invariants, while its handler also validates empty paragraphs and checks duplicate title/order using repositories. Separate aggregate-local invariants from cross-aggregate uniqueness checks.
- This count does not include every throw in application/presentation; the HTTP filter maps several exception types, but non-domain throws still need an inventory.

### Persistence, concurrency, and MongoDB

- `BaseMongoRepository` has been removed. Persistence and pagination behavior now live in the affected feature repositories, where each feature can keep its own versioning, session, and read-model requirements.
- Reading rooms, chapters, books, and posts use compare-and-swap by version. Legacy documents missing `version` are treated as version 0; repository-side view/like/reorder/status mutations increment it so stale aggregate writes fail with 409.
- No per-query `explain('executionStats')` was run. Index adequacy and COLLSCAN risk remain unverified. Schema indexes, uniqueness, autoIndex, and array growth belong in step 4.
- The source checked did not show common `maxTimeMS`, pool-size, majority writeConcern, or index migration configuration. Verify deployment/runtime before concluding.

### Authorization

- CASL rules are centralized in `shared/src/ability/define-ability.ts`. Several handlers check permissions on loaded instances (posts, comments, reviews, collections, highlights).
- There is not yet a complete endpoint matrix for instance checks and DB-level list filtering; IDOR risk is not cleared.
- The source scan found no NestJS/Mongoose/CASL imports in module domain folders. The architecture boundary check passes.

### Pagination, idempotency, and event delivery

- Cursor pagination exists in some lists; offset is still common. OpenAPI shows several query DTOs exposing page/current/pageSize/cursor together; verify which parameters each route actually uses.
- No shared HTTP `Idempotency-Key` guard/decorator was found. Queue/job deduplication does not replace HTTP write idempotency.
- Book create/update/delete now write a Mongo outbox record in the same transaction as the Book change. A worker relay claims records with a lease and enqueues idempotently identified BullMQ jobs; published records expire after 30 days. This protects the Chroma indexing side effect. Other `EventEmitter` events remain process-local and need separate criticality review; this is not yet a system-wide outbox.

### External calls and caching

- Google OAuth token exchange and all GitHub OAuth requests now use 10-second abort signals; ElevenLabs audio generation uses a 60-second abort signal. OpenAI-compatible requests already use a configurable Axios timeout (15 seconds by default). Focused tests verify timeout signals are attached. No automatic retry was added: OAuth codes are single-use, and retrying paid TTS requests can duplicate work.
- Chroma writes now pass the domain document ID to LangChain as the Chroma record ID. Batch splitting is limited to errors that explicitly indicate a size limit and runs sequentially; connection/server failures return a failed batch so BullMQ applies retry/backoff instead of multiplying requests. The Chroma queue uses shared three-attempt exponential backoff defaults; reconciliation retries retained failed jobs. Book outbox jobs keep their explicit five-attempt policy. Chroma's `fetchOptions` cannot accept a fresh `AbortSignal` for each request, so its connection factory now shares an Undici dispatcher instead: defaults are 10 seconds to connect, 15 seconds for response headers, and 30 seconds between response body chunks. These are transport phase/inactivity limits, not a strict total request deadline. Values are configurable with `CHROMA_CONNECT_TIMEOUT_MS`, `CHROMA_HEADERS_TIMEOUT_MS`, and `CHROMA_BODY_TIMEOUT_MS`. No common outbound-call wrapper or circuit breaker was found.
- No HTTP `ETag`/`Cache-Control` implementation was found in the scanned source. Redis application caching is not HTTP caching.

### Observability and security automation

- Pino request ID, `x-request-id`, Problem Details `traceId`, and redaction of some auth/cookie/password/token fields exist. OpenTelemetry, RED metrics, and SLO configuration were not found.
- Body/upload limits, JWT/CSRF, Helmet, and env-based CORS exist. Dependency scan, SBOM, and secret scanning were not found in the reviewed PR workflow.

### Architecture and documentation

- Module boundary checker and ADRs exist. The checker now resolves alias and relative paths, scans static imports/exports and dynamic imports/`require()`, and rejects cross-module private imports. It passed over 1,015 TypeScript files; a temporary relative deep-import probe was rejected as expected. The current source inventory has no cross-module private imports.
