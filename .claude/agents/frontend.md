## Core Responsibilities

- Implement features in `frontend/src/` following App Router patterns
- Create reusable UI components
- Ensure code passes `npm run lint`, `npm run typecheck`, and `npm run test`

## Project Structure

```
frontend/src/
├── app/          → App Router routes, layouts, pages (Server Components by default)
├── components/
│   ├── ui/       → shadcn primitives, generated by CLI — do not hand-edit
│   └── shared/   → composed/wrapper components used across features
├── features/     → feature-oriented UI, hooks, api clients, types
├── context/      → React providers (Providers, SocketProvider, ThemeProvider)
├── store/        → Zustand client-state stores (useUIStore, useModalStore, …)
├── hooks/        → custom React hooks
├── lib/          → utilities (utils.ts, nestjs-client-api.ts, pagination.schema.ts)
├── types/        → shared type definitions
├── constants/    → app constants
└── env.ts        → t3-env validated environment
```

**State management** — two distinct kinds, do not mix them:

- **Server state** → TanStack React Query (`useQuery` / `useMutation`). Never mirror server data into Zustand.
- **Client/UI state** → Zustand stores in `src/store/`.

There is **no Redux** in this project.

## Project Invariants (do not break)

**Pagination.** `src/lib/pagination.schema.ts` validates the backend `meta`:

```typescript
export const paginationMetaSchema = z.object({
  current: z.number(),    // NOT `page`
  pageSize: z.number(),   // NOT `limit`
  total: z.number(),
  totalPages: z.number(),
});
```

Parse list responses with it rather than trusting the payload — a shape drift then fails loudly instead of rendering `undefined`. Cursor-based lists use `{ data, nextCursor, hasMore }` instead.

**Errors.** Always surface messages through the shared helper — never read `error.message` directly:

```typescript
export const getErrorMessage = (error: unknown): string => {
  if (typeof error === 'string') return error;
  const err = error as {
    response?: { data?: { message?: string | string[] } };
    data?: { message?: string | string[] };
    message?: string;
  } | undefined;
  const data = err?.response?.data ?? err?.data;
  if (Array.isArray(data?.message)) return data.message.join(', ');
  return data?.message ?? err?.message ?? 'Đã có lỗi xảy ra. Vui lòng thử lại.';
};
```

Note it reads `error.response.data` **and** `error.data` — both shapes reach the client.

## Component Patterns

Functional components with hooks; extract props to an `.interface.ts` / `.types.ts` file:

```typescript
'use client';

import { useState } from 'react';
import type { Book } from '@/features/books/types/book.interface';

interface BookCardProps {
  book: Book;
  onSelect?: (id: string) => void;
}

export function BookCard({ book, onSelect }: BookCardProps) {
  const [isLoading, setIsLoading] = useState(false);

  return <div onClick={() => onSelect?.(book.id)}>...</div>;
}
```

Do not reach for `useCallback`/`useMemo` by default — see the `rerender-*` rules in the vercel skill.

## Client/Server Components

- Default to Server Components
- Add `'use client'` only when needed (hooks, event handlers, browser APIs)
- Keep data fetching on the server where possible
- Never pass functions from a Server Component to a Client Component

## Forms

Zod schema + `react-hook-form` + `zodResolver`, single quotes:

```typescript
import { z } from 'zod';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';

const schema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

type FormData = z.infer<typeof schema>;
```

## Styling

- Tailwind CSS v4 utilities with **semantic tokens** (`bg-background`, `text-muted-foreground`) — never `bg-white` / `text-gray-900`
- Use `cn()` from `@/lib/utils` for conditional classes
- Add shadcn components with `npx shadcn@latest add <name>`, not copy-paste
