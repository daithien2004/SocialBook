# Tailwind CSS v4

## Overview

This project uses **Tailwind CSS v4** with a **CSS-first configuration**. There is no `theme.extend` in a JS config — theme values are declared in CSS via `@theme`, and design tokens are generated from `design-tokens/tokens.json` through **Style Dictionary**.

## Trigger

Activate when working on:
- Tailwind classes and utilities
- Theme colors, spacing, radius
- Design tokens (`design-tokens/`)
- Dark mode
- shadcn/ui theming
- Responsive layouts

## How Tailwind v4 Differs from v3

| v3 | v4 (this project) |
|----|-------------------|
| `tailwind.config.js` with `theme.extend` | `@theme { }` blocks in CSS |
| `@tailwind base/components/utilities` | `@import "tailwindcss"` |
| `darkMode: 'class'` in JS config | `@custom-variant dark (&:is(.dark *))` |
| Plugin-based config | CSS-first, `@plugin` when needed |

## Entry Point

```css
/* frontend/src/app/globals.css */
@import "tailwindcss";
@import "./tokens.generated.css";        /* ← generated, do not edit by hand */

@custom-variant dark (&:is(.dark *));     /* dark mode = .dark ancestor */
```

## Design Tokens (Source of Truth)

```
frontend/design-tokens/
├── tokens.json      ← edit THIS
└── config.mjs       ← Style Dictionary config
```

`npm run build:tokens` runs Style Dictionary and emits `tokens.generated.css`. `predev` and `prebuild` run it automatically — but after editing `tokens.json` while `dev` is already running, regenerate manually:

```bash
cd frontend
npm run build:tokens
```

**Never** hand-edit `tokens.generated.css` — it is overwritten on every build.

## The `@theme` Block

Tailwind v4 maps CSS custom properties to utility classes. `@theme inline` references the shadcn CSS variables so utilities stay in sync with the light/dark values:

```css
@theme inline {
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);

  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-destructive: var(--destructive);
  --color-border: var(--border);
  --color-ring: var(--ring);
  /* ...chart, success, warning, info tokens */
}
```

Declaring `--color-primary` here makes `bg-primary`, `text-primary`, `border-primary` available.

## Colors: Use Semantic Tokens

Use **semantic** utilities backed by CSS variables — never raw hex:

```tsx
// ✅ Theme-aware, works in light and dark
<div className="bg-background text-foreground border-border">
<button className="bg-primary text-primary-foreground hover:bg-primary/90">
<p className="text-muted-foreground">
<div className="text-destructive">

// ❌ Raw colors break theming
<div className="bg-white text-gray-900">
```

Opacity modifiers work on token colors: `bg-primary/90`, `text-foreground/60`.

## Dark Mode

Dark mode is **class-based** (`.dark` on an ancestor, toggled by next-themes):

```css
@custom-variant dark (&:is(.dark *));
```

With semantic tokens you rarely need `dark:` — `bg-background` already resolves per theme. Use `dark:` only for genuinely theme-specific overrides:

```tsx
<div className="bg-background dark:bg-card">
```

## Class Merging with `cn()`

Always compose conditional classes through `cn()` (clsx + tailwind-merge) so later classes win:

```tsx
import { cn } from '@/lib/utils';

<div className={cn('rounded-lg border p-4', isActive && 'border-primary', className)} />
```

Never concatenate class strings manually — conflicting utilities won't be deduped.

## Responsive Design

Mobile-first: unprefixed = smallest, then `sm:` `md:` `lg:` `xl:` `2xl:`.

```tsx
<div className="grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3">
```

- Layout: flex/grid utilities, not media queries in CSS.
- Container queries are available (`@container`) when a component must respond to its own width.

## Component Patterns

Use **`cva`** (class-variance-authority) for multi-variant components — the same pattern shadcn/ui uses:

```tsx
import { cva, type VariantProps } from 'class-variance-authority';
import { cn } from '@/lib/utils';

const badgeVariants = cva(
  'inline-flex items-center rounded-full px-2.5 py-0.5 text-xs font-medium',
  {
    variants: {
      variant: {
        default: 'bg-primary text-primary-foreground',
        secondary: 'bg-secondary text-secondary-foreground',
        destructive: 'bg-destructive text-destructive-foreground',
        outline: 'border border-border text-foreground',
      },
    },
    defaultVariants: { variant: 'default' },
  },
);

interface BadgeProps extends React.HTMLAttributes<HTMLSpanElement>, VariantProps<typeof badgeVariants> {}

export function Badge({ className, variant, ...props }: BadgeProps) {
  return <span className={cn(badgeVariants({ variant }), className)} {...props} />;
}
```

## Animations

- Prefer CSS transitions on token-driven properties: `transition-colors`, `transition-transform`.
- For enter/exit orchestration use **Framer Motion** (already a dependency), not Tailwind keyframes.
- Respect `motion-reduce:` for accessibility.

## Accessibility

- Never rely on color alone — pair with text/icon.
- Keep focus states visible: `focus-visible:ring-2 focus-visible:ring-ring`.
- Use `sr-only` for screen-reader-only text.

## Anti-Patterns

- ❌ Editing `tokens.generated.css` — regenerated on every build.
- ❌ Adding `theme.extend` to `tailwind.config.ts` — theme lives in CSS `@theme`.
- ❌ `@tailwind base;` directives — v4 uses `@import "tailwindcss"`.
- ❌ Raw hex/`bg-white`/`text-gray-900` — use semantic tokens.
- ❌ Manual class concatenation instead of `cn()`.
- ❌ `dark:` everywhere when a semantic token already handles it.
